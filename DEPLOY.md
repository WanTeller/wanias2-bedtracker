# Deploying WaniaS2 BedTracker (free, ~15-20 users)

**Hosting:** Render (free web service) + **Neon** (free PostgreSQL that never
expires). Total cost: $0. No credit card.

The repo is already prepared: `render.yaml`, `build.sh`, `Procfile`,
`runtime.txt`, WhiteNoise for static files, `/healthz/` health check, PWA files,
and production-hardened settings.

---

## Step 1 — Put the code on GitHub

You need a free GitHub account. In the project folder's PowerShell window:

```powershell
git remote add origin https://github.com/<your-github-username>/wanias2-bedtracker.git
git push -u origin main
```

(Create the empty repo first at <https://github.com/new> — name it
`wanias2-bedtracker`, **don't** add a README/licence.)

---

## Step 2 — Create the database on Neon

1. Sign up at <https://neon.tech> (free, no card). Sign in with GitHub.
2. **Create project** → name it `wanias2-bedtracker`, region **AWS ap-southeast-1
   (Singapore)** (closest free region), Postgres 16.
3. On the project dashboard, open **Connection Details**. Copy the
   **Connection string** — it looks like:

   ```
   postgresql://neondb_owner:XXXX@ep-aaaa-bbbb-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

   Keep this tab open — you need this string in Step 3, and the
   **direct (non-pooler)** host for the backup (Step 6).

---

## Step 3 — Create the web service on Render

1. Sign up at <https://render.com> (free, no card). Sign in with GitHub.
2. **New +** → **Blueprint** → pick your `wanias2-bedtracker` repo → **Apply**.
   Render reads `render.yaml` and creates the service.
3. It will ask for the three secret values (`sync: false` in the blueprint).
   Enter them (see the table below), then let it deploy.
4. First deploy takes ~3-5 min. When it's live, Render shows the URL:
   **`https://wanias2-bedtracker.onrender.com`** (or `-xxxx` if the name was taken).
5. Go back to the service's **Environment** tab and set
   `BEDTRACKER_ALLOWED_HOSTS` and `BEDTRACKER_CSRF_TRUSTED_ORIGINS` to that exact
   URL (see table), then **Manual Deploy → Deploy latest commit** once more.

### Required environment variables

| Variable | Value |
|---|---|
| `BEDTRACKER_DEBUG` | `false` *(already set by the blueprint)* |
| `BEDTRACKER_SECRET_KEY` | *auto-generated by Render — leave it* |
| `DATABASE_URL` | the Neon connection string from Step 2 |
| `BEDTRACKER_ALLOWED_HOSTS` | `wanias2-bedtracker.onrender.com` *(host only, no `https://`)* |
| `BEDTRACKER_CSRF_TRUSTED_ORIGINS` | `https://wanias2-bedtracker.onrender.com` |
| `PYTHON_VERSION`, `WEB_CONCURRENCY` | *set by the blueprint — leave them* |

Optional (only if you want real password-reset emails):
`BEDTRACKER_EMAIL_HOST`, `BEDTRACKER_EMAIL_PORT`, `BEDTRACKER_EMAIL_USER`,
`BEDTRACKER_EMAIL_PASSWORD` (a free Gmail "app password").

To turn on name-only testing login in production, add
`BEDTRACKER_SIMPLE_LOGIN` = `true`.

## Step 4 — Create your admin account

In the Render dashboard: your service → **Shell** tab:

```
python manage.py createsuperuser
```

(Username = your email.) Then log in at
`https://wanias2-bedtracker.onrender.com/admin/`.

Optionally load the task categories + demo data:

```
python manage.py seed_demo
```

---

## Step 5 — Updating / redeploying later

Just push to GitHub:

```powershell
git add -A
git commit -m "describe your change"
git push
```

Render redeploys automatically (`autoDeploy: true`). `build.sh` runs
`collectstatic` and `migrate` every deploy, so new database changes apply
themselves. Watch progress on the Render **Events**/**Logs** tab.

---

## Step 6 — Point the Windows backup at the production database

Your existing local backup system doesn't change — it just gets Neon's details.

1. `backup\backup.env` (copy from `backup.env.example` if you haven't):

   ```
   DB_KIND=postgres
   PG_HOST=ep-aaaa-bbbb.ap-southeast-1.aws.neon.tech      # DIRECT host: remove "-pooler"
   PG_PORT=5432
   PG_DB=neondb
   PG_USER=neondb_owner
   PG_SSLMODE=require
   REQUIRE_INTERNET=true
   ```

2. Put the password in `%APPDATA%\postgresql\pgpass.conf` (create the folder),
   **one line**:

   ```
   ep-aaaa-bbbb.ap-southeast-1.aws.neon.tech:5432:neondb:neondb_owner:THEPASSWORD
   ```

3. Install the PostgreSQL client tools (for `pg_dump`/`pg_restore`) if you don't
   have them: <https://www.postgresql.org/download/windows/> → run the installer,
   you only need "Command Line Tools". Then either add its `bin` folder to PATH
   or set `PG_DUMP` / `PG_RESTORE` in `backup.env`.

4. Test:

   ```powershell
   cd backup
   .\.venv\Scripts\python.exe backup_bedtracker.py --force
   .\.venv\Scripts\python.exe backup_bedtracker.py --verify LATEST
   ```

The scheduled task (already registered) keeps working — it now backs up Neon
instead of the local SQLite file. Backups still land in
`...\BedTracker\backup\` and are never in Git.

## Free-tier limits to know

| | Limit | Impact |
|---|---|---|
| **Render web** | Sleeps after **15 min** with no traffic; ~50s to wake | First hit after a quiet spell is slow. During a shift with people using it, it stays awake. |
| **Render web** | 512 MB RAM, 0.1 CPU, 100 GB bandwidth/mo, 500 build min/mo | Fine for 15-20 users. |
| **Neon** | **0.5 GB** storage, never expires, no card | This app's data is tiny (KB per patient). Years of use fits. |
| **Neon** | Compute sleeps after 5 min idle, ~0.5s to wake; 100 compute-hours/mo | Fine for shift-pattern use. |
| **Render Postgres** | *(not used — it expires in 30 days; that's why we use Neon)* | — |

## If you outgrow the free tier

- **Remove the wake-up delay:** Render **Starter** web service = **$7/month**
  (always on). Nothing else changes. This is the single most useful upgrade.
- **More database room / no compute sleep:** Neon **Launch** = **$19/month**
  (10 GB, autoscaling). Only needed if data grows a lot or usage is heavy.
- **Custom domain** (e.g. `bedtracker.yourhospital.com`): add it in Render's
  dashboard, create one DNS record, then add the domain to
  `BEDTRACKER_ALLOWED_HOSTS` and `BEDTRACKER_CSRF_TRUSTED_ORIGINS`. No code
  change. Render gives a free TLS certificate.
